## 🕵️ Правила безопасности оператора (как не «засветить» сервер)

Чтобы ваш VPS и панель управления оставались невидимыми для сетевых сканеров (Shodan/Censys) и систем глубокой фильтрации трафика (DPI), соблюдайте базовую сетевую гигиену.

### 1. Скрытие веб-интерфейса панели (3x-ui)

* **Закройте порт панели в фаерволе.** Веб-интерфейс (порт `2053` или любой другой) не должен быть открыт в интернет по IP. Снаружи должны быть доступны только порт Xray (`443`) и порт SSH.
* **Входите в панель только через SSH-туннель.** Пробрасывайте порт панели локально на свой компьютер:
  ```bash
  ssh -L 2053:127.0.0.1:2053 user@your-vps-ip
  ```
  После этого панель открывается в браузере по адресу `http://127.0.0`, а извне порт полностью невидим.
* **Используйте случайный путь (Web Base Path).** Задайте в настройках панели длинный случайный префикс из 16–24 символов (например, `/x9kLm2pQ8vR4tW7z/`), чтобы при случайном запросе сервер не выдавал страницу входа 3x-ui.
* **Никакого открытого HTTP.** Если вы открываете панель через домен, обязательно используйте обратный прокси (Nginx / Caddy) с действующим TLS-сертификатом. Вход по обычному HTTP передаёт пароль и куки в открытом виде.

### 2. Сетевая маскировка и выбор SNI (Reality)

* **Выбирайте «соседний» сайт-маску.** Домен для Reality (SNI) должен находиться в той же стране или дата-центре, что и ваш VPS, поддерживать **TLS 1.3** и **HTTP/2**, и не быть заблокированным в стране клиента. Несовпадение географии IP сервера и сайта-маски (например, VPS в Нидерландах, а SNI — российский сайт) создаёт аномалию задержек для DPI.
* **Избегайте популярных SNI из публичных гайдов.** Не используйте `google.com`, `microsoft.com`, `apple.com` или `yahoo.com` — такие домены находятся под усиленным мониторингом. Найдите небольшой локальный сайт на том же хостинге (например, сайт местного университета, музея или регионального магазина).
* **Не смешивайте Reality и веб-сайты на одном порту.** Если на порту `443` работает Reality с чужим SNI, не привязывайте к этому же IP свой домен с панелью управления без разделения через SNI-роутер (Nginx stream).

### 3. Гигиена ключей и подписок (Subscriptions)

* **Отключите сервер подписок (Subscription).** Если у вас 3–5 личных пользователей, безопаснее полностью отключить сервис подписок в настройках панели и передавать ключи (`vless://...`) вручную. Открытый порт подписок легко опознаётся сканерами по характерным HTTP-заголовкам.
* **Не проверяйте сервер в публичных онлайн-чекерах.** Никогда не вставляйте свои рабочие ключи `vless://` и IP-адрес сервера в сомнительные веб-чекеры или Telegram-боты — многие из них собирают базу рабочих узлов.
* **Используйте форк без телеметрии.** В чистой сборке вырезаны фоновые запросы к серверам спонсоров и проверке обновлений, которые могут выдавать сервер по характерному исходящему TLS SNI.

### 4. Базовая безопасность ОС сервера

| Параметр | Рекомендуемая настройка | Зачем это нужно |
| :--- | :--- | :--- |
| **Доступ по SSH** | Только по SSH-ключу (`PasswordAuthentication no`), нестандартный порт | Защита от автоматического перебора паролей ботами |
| **ICMP (Ping)** | Отключён в фаерволе (UFW / iptables) | Сервер не отвечает на массовое сканирование подсетей |
| **Посторонний софт** | Запрещены торренты, парсеры и публичные сервисы на этом же VPS | Исключает жалобы (Abuse) и блокировку IP-адреса хостером |




> [!CAUTION]
> ⚠️ **Не используйте `dev-latest` / pre-release сборки**
>
> Сборки `dev-latest` (и любые pre-release) собираются автоматически из свежего `main` upstream и **не проходят ручное тестирование**. Они могут содержать:
>
> - **Критические уязвимости** (например, CVE-2026-98432 в Xray-core v26.10.29, связанная с MPTCP и позволяющая удалённое получение root).
> - **Сломанные конфигурации** (несовместимость формата, регрессии в работе протоколов).
>
> **Для обновления используйте только стабильные релизы** через кнопку «Обновить» в панели (Settings → Panel) или через `install.sh` с конкретным тегом. Не устанавливайте `dev-latest` на боевой сервер.
